# 01. プロダクトビジョン

状態: 確定案（ただし後述の Go/No-Go 条件付き）
確信度: 中（技術制約は一次資料で確認済み、市場の受容性は未検証）

## 1. 一文で言うと

**「Google の完全ログインと Widevine の実再生が確認できない場合に、それらを必要としない Web 用途に絞り、待機・メモリのベースラインを既存ブラウザより小さくし、既定で追跡と広告を遮断する、Windows 向けの小型ブラウザ。起動は Edge より遅い（PX3c）。」**

PX1 では Google OAuth の識別子画面とパスキーのプロンプトが動作した。完全ログインが通れば、対象は広がる。以下の記述は、完全ログインが未検証であることを前提にする。

これは Chrome/Edge の完全代替ではない。完全代替を掲げた瞬間に、後述の互換性の壁に当たる。

## 2. 解く問題

既存ブラウザは、一般的な利用者にとって次の点で過剰である。

| 過剰さ | 具体的なコスト | 本プロジェクトの狙い |
|---|---|---|
| 機能の多さ | 同期、アカウント、AI、ショッピング、ニュース、サイドバー、拡張機能ストア | 機能を削り、待機とメモリの固定費を下げる。起動は別問題 |
| バックグラウンド処理 | 更新、テレメトリ、クラッシュ送信、プリロード、同期 | 常駐処理を最小化し、アイドル CPU を下げる |
| 既定のデータ保存 | 履歴、キャッシュ、オートフィル、パスワード、Cookie の長期保持 | 保存を限定し、削除を明確にする |
| 追跡の既定値 | 第三者トラッカーをある程度許容 | 既定で強い遮断を選ぶ |
| 攻撃面 | 拡張機能、PDF 注釈、Web Payment、Push、同期 | 使わない機能を無効化し、ホスト側の露出を減らす |

ただし「機能を削る」ことは、Web 互換性とセキュリティを削ることと同義ではない。削ってよいのは**使わない機能**であり、**エンジンのサンドボックス・サイト分離・TLS 検証・証明書検証**は削らない。これは設計上の不変条件である。

## 3. 対象ユーザー

### 3.1 主対象

- Windows 11 を日常使いし、作業の中心が「読む・調べる・書く・社内 SaaS を使う」人。
- Google アカウントでのログインを、このブラウザ内で完結させる必要がない人。
- Netflix などの Widevine DRM 配信を、このブラウザの主目的にしない人（PX4 の実再生が通れば、この制限は外れる）。
- Chrome 拡張機能を常用していない人。
- メモリ 8GB 以下の端末、または常時多数のアプリを開く人。
- テレメトリやアカウント同期を望まない人。

### 3.2 副次対象

- 特定の Web アプリだけを使う業務端末（kiosk に近い用途）。
- 調査・読解用の「2 台目ブラウザ」。メインブラウザと分離したい人。

### 3.3 対象外

- Google Workspace をブラウザ内ログインで常用する人（Gmail、Drive、Google カレンダー）。ただし、PX1 で完全ログインが通れば、この制限は外れる。
- Netflix、Amazon Prime Video、Disney+ などを主目的にする人。PX4 で実再生が通れば、この制限は外れる。
- Chrome 拡張機能が必須の人。
- パスワードマネージャ、同期、拡張機能ストアを求める人。

### 3.4 対象定義の自己批判

この対象ユーザーは、需要調査から導いたものではなく、**WebView2 の制約から逆算した面**がある。「Google ログインを必要としない人」という定義は、その典型である。したがって、Phase 0 で「対象ユーザーの何割が Google ログインを必要とするか」を調査し、過半ならこの定義を撤回する。詳細は [13-refutation-review.md](13-refutation-review.md) の F1。

## 4. 提供価値（主張してよいこと・いけないこと）

| 主張 | 可否 | 根拠・条件 |
|---|---|---|
| 起動が速い | **主張しない** | PX3c で暖機後 1 タブ 481ms vs Edge 293ms、5 タブ 456ms vs 310ms。Edge の方が速い |
| アイドル CPU が低い | 主張してよい（目標） | バックグラウンド処理を限定。実測で判定する |
| 1〜5 タブの総メモリが小さい | 主張してよい（目標） | ホストの固定費を小さくする。実測で判定する |
| 20〜50 タブでも Edge より軽い | **主張しない** | Edge は sleeping tabs を持つ [S27]。同等以下になる可能性がある |
| 広告遮断が uBO/Brave と同等 | **主張しない** | WebView2 の通信フックには構造的な制約がある [S09][S10] |
| Chrome より安全 | **主張しない** | エンジンは同じ Chromium 系。ホスト側の新規コード分だけ攻撃面が増える |
| Google ログインができる | **主張しない** | ポリシーで拒否される [S08][S20] |
| Netflix が見られる | **主張しない** | PX4 で EME は supported だが、実再生は未検証 [S48] |
| 拡張機能が使える | **主張しない** | WebView2 は非対応・設定不可 [S08] |

この表の「主張しない」は、弱気ではなく**製品契約**である。ここを曖昧にすると、ユーザーは「Chrome の代わり」と誤解し、導入後に失望する。

## 5. 非目標

- ブラウザアカウント、クラウド同期、履歴同期
- 拡張機能ストア、ユーザースクリプトの一般公開
- 内蔵 AI、ニュース、サイドバー、ポイント、報酬
- パスワードマネージャ（保存もしない）
- テレメトリ、クラッシュログの自動送信
- 複雑な設定画面（設定は 1 画面に収める）
- 独自レンダリングエンジン、独自 TLS スタック
- User-Agent 偽装による認証制限の回避
- 証明書エラーの例外処理
- DRM の回避、広告の「非表示だけ」で請求を回避する設計

## 6. 競合との差分

数値は実測前なので置かない。差分の方向だけを示す。

| 軸 | Chrome | Edge | Brave | Firefox | 本製品（狙い） |
|---|---|---|---|---|---|
| エンジン | Chromium | Chromium | Chromium | Gecko | WebView2 (Chromium) |
| 拡張機能 | あり | あり | あり（Chrome 互換） | あり | なし |
| 広告遮断 | なし（拡張で追加） | 限定的 | 標準 | 限定的 | 標準（ただし uBO 同等ではない） |
| Google ログイン | 可 | 可 | 可 | 可 | 条件付き（PX1 で識別子画面。完全ログイン未検証） |
| Widevine DRM | 可 | 可 | 可 | 可 | 条件付き（EME supported、実再生未検証） |
| 同期 | あり | あり | あり | あり | なし |
| テレメトリ | あり（opt-out） | あり | あり（opt-out） | あり | なし |
| 起動の固定費 | 大 | 大 | 中 | 中 | 小（目標、PX3c 未達） |
| 多タブ時のメモリ | 中 | 小（sleeping tabs） | 中 | 中 | 要実測 |
| 攻撃面（ホスト） | 大 | 大 | 大 | 大 | 小（狙い） |

この表から分かる通り、本製品が勝てるのは「固定費」「プライバシー既定値」「攻撃面の小ささ」であり、「機能」「互換性」「多タブ効率」ではない。広告遮断は Brave と競合するが、エンジン内蔵の遮断ではないため同等性は主張できない。

## 7. 価値前提（normative）

この設計は、次の価値判断の上に成り立っている。事実ではないので明示する。

1. **プライバシーは既定値で守るべきで、ユーザーの設定努力に依存すべきでない。** したがって追跡遮断は既定で強くする。
2. **使わない機能は、無効化する方が安全である。** 攻撃面は機能数に比例する。
3. **互換性の欠落は、隠さず製品契約に書く。** 「動かないサイトがある」ことを事前に明示する方が、事後の信頼失墜よりよい。
4. **セキュリティ更新の速度は、自前実装の自由度より優先する。** 小規模チームが Chromium をフォークして更新を遅らせるより、Microsoft の更新に乗る方が安全である。
5. **性能目標は実測で判定し、達成しなければ主張を撤回する。** マーケティング文句を先に固定しない。

価値4は、後述の技術選定（WebView2 採用、Chromium fork 不採用）の根拠である。性能を最大化するために fork する選択は、更新遅延というセキュリティ費用を伴う。この費用を支払える組織でなければ、fork は合理的でない。

## 8. 成功指標と Kill criteria

### 8.1 成功指標（プロダクト）

| 指標 | 測定方法 | 合格ライン（案） |
|---|---|---|
| コールドスタート中央値 | 09 の手順 | 同一環境の Edge より短い |
| 5 タブ総メモリ中央値 | 09 の手順 | 同一環境の Edge 以下 |
| 20 タブ総メモリ中央値 | 09 の手順 | Edge の +10% 以内（勝ちとは言わない） |
| タブ切替（warm）p95 | 09 の手順 | 100ms 未満 |
| アイドル CPU（10 分平均） | 09 の手順 | Edge 以下 |
| 広告遮断によるページ読み込み悪化 | 09 の手順 | 中央値 +3% 以内 |
| クラッシュフリー率（8 時間） | 自動継続試験 | 99% 以上 |

これらは【目標】であり、達成を約束しない。測定前に「勝った」と主張しない。

### 8.2 Kill criteria（中止条件）

次のいずれかに該当したら、製品化を中止するか、製品定義を変える。

1. Phase 0 の計測で、5 タブ総メモリが Edge を下回らない、かつ起動も Edge を下回らない（PX3c で起動は未達）。
2. WebResourceRequested の往復コストが、ページ読み込み中央値を 10% 以上悪化させる。
3. Google ログインが必要な主要サイトが、対象ユーザーの利用の 30% 以上を占める。
4. ホストの攻撃面（独自コード）が、削減できる固定費を上回るセキュリティ費用を生むと監査で判断される。
5. 1 人の開発で 6 か月以内に「日常利用できる最小機能」に到達できない。

## 9. なぜ「完全代替」を諦めるのか

これは妥協ではなく、一次資料に基づく制約である。

- WebView2 はブラウザ拡張を提供しない。設定もできない [S08]。
- Google は埋め込み WebView からの OAuth を 2021-09-30 以降拒否している [S20][S21]。
- WebView2 は Web Push、Payment API、Periodic Background Sync を提供しない [S08]。
- Widevine DRM は公式には WebView2 で未提供とされるが、PX4 では EME が supported を返した。実再生は未検証である [S48]。
- Google のポリシーは、埋め込みホストが通信を傍受しスクリプトを注入できることを、拒否理由として明示している [S20]。広告遮断のために通信フックとスクリプト注入を行う本設計は、まさにその threat model に該当する。

これらの制約は、実装の工夫だけでは解消しないものと、PX1/PX4 で一部反証されたものを含む。解消するには Chromium の完全なフォーク（拡張・認証を自前で成立させる）が必要な場合があり、それは小規模チームの保守能力を超える。だから製品定義を絞る。

## 10. 用語

| 用語 | 定義 |
|---|---|
| ホスト | 本ブラウザのネイティブプロセス。UI、タブ管理、フィルタ、保存を担当する |
| エンジン | WebView2 Runtime。Chromium のレンダリングとネットワークを担当する |
| タブ | 1 つの WebView2 コントローラと、その状態（URL、履歴、サスペンド状態）の組 |
| Warm | 非表示だがサスペンドしていないタブ。切替が速い |
| Cool | 非表示で `TrySuspendAsync` 済みのタブ [S11] |
| Cold | WebView2 を破棄し、URL とスクロール位置だけ保持したタブ |
| フィルタ | 広告遮断ルール。EasyList 系の構文を adblock-rust で解釈する |
| スクリプトレット | ページ内で実行する小さな JS。フィルタ由来のものを含む |
