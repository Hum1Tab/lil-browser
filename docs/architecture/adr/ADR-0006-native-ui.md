# ADR-0006: UI はネイティブ（Win32）にする

状態: 採用
日付: 2026-10-23

## 文脈

ブラウザの UI（タブストリップ、アドレスバー、メニュー）を、Web 技術で作るか、ネイティブで作るか。Tauri や Electron は Web UI を前提にする。

## 決定

Win32 + Direct2D/DirectWrite のネイティブ UI にする。アドレスバーは Win32 の EDIT を使う。

## 理由

1. Web UI は、UI 用にもう 1 つレンダラを必要とする。メモリと起動の固定費が増える。
2. ネイティブ UI は、ページのレンダラとプロセスを分けられる。UI のクラッシュがページに影響しにくい。
3. アドレスバーの IME は、Win32 の EDIT が最も確実である。
4. タブストリップの描画を Direct2D で行えば、大量のタブでも軽い。

## 結果

- UI の実装コストが高い。アクセシビリティ（UIA）も自前。
- デザインの自由度は Web UI より低い。
- ページの上に重ねる UI（オーバーレイ）は、HWND の Z オーダーに注意する。

## 代替案

- Web UI（Tauri / Electron）: 実装は速いが、固定費が増える [S04]。
- WinUI 3: アクセシビリティは良いが、Windows App SDK の依存と起動コストが増える。未検証。
- egui / iced: 日本語 IME の品質が未検証。住所バーには不適。

## 再検討のトリガー

- ネイティブ UI の工数が M1 の 2 倍を超える。
- アクセシビリティの要件が、自前実装では満たせない。
