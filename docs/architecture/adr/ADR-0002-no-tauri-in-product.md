# ADR-0002: 製品に Tauri v2 を使わない

状態: 採用
日付: 2026-10-23

## 文脈

Tauri v2 は Rust でデスクトップアプリを作るための枠組みで、小さいバイナリ、ウィンドウ、バンドラ、署名付きアップデータを提供する。ブラウザの土台として魅力的に見える。

## 決定

製品には Tauri v2 を使わない。Phase 0 の計測スパイクにだけ使う。

## 理由

1. Tauri は全 WebView に `isTauri` と `__TAURI_INTERNALS__` を注入する [S02]。リモートページにも入る。
2. ブラウザに必要な通信フック、プロファイル、サスペンドは、Tauri の公開 API では足りず、結局 COM を直接叩く。
3. 複数 WebView は `unstable` feature である [S03]。
4. バイナリサイズの利点は、エンジンがシステムにあるブラウザでは支配要因にならない [S04]。

## 結果

- ウィンドウ、タブ、UI を自前で実装する。工数は増える。
- 攻撃面は小さくなる。コンテンツページに IPC ブリッジが無い。
- アップデータ、バンドラ、トレイなどの便利機能は自前で用意する。

## 代替案

- wry を直接使う: Tauri より薄い。IPC の自動注入が無い [S36]。ウィンドウ管理は自前。
- Tauri を使う: 試作では最速。製品では IPC 注入と抽象の不一致が残る。

## 再検討のトリガー

- Tauri が「コンテンツ WebView に何も注入しない」モードを提供する。
- 複数 WebView が stable になり、通信フックとプロファイルが公開 API になる。
