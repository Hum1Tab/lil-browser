# ADR-0008: 更新とフィルタは署名検証を必須にする

状態: 採用
日付: 2026-10-23

## 文脈

ブラウザの更新機構とフィルタ配布は、任意コード実行につながる経路である。更新サーバー、DNS、フィルタ配布元のいずれかが侵害されると、ユーザー全体が危険にさらされる。

## 決定

- アプリ更新: マニフェストに Ed25519 署名、パッケージに SHA-256 と Authenticode 署名。ダウングレードを拒否する。
- フィルタ更新: バンドルに Ed25519 署名と SHA-256。前版を保持し、失敗時はロールバックする。
- 署名鍵はオフラインで保管し、ビルド環境と分離する。
- 署名検証に失敗した更新は適用しない。

## 理由

1. TLS だけでは、配布元の侵害や DNS 攻撃を防げない。
2. 署名をクライアント側で検証すれば、配布経路の信頼性を下げられる。
3. ダウングレード拒否により、既知の脆弱性への巻き戻しを防げる。

## 結果

- 鍵の管理とローテーションの運用が必要。
- 署名の失敗で更新が止まるため、監視とアラートが必要。
- フィルタの更新が止まると、遮断率が下がる。ユーザーに状態を表示する。

## 代替案

- TLS のみ: 配布元侵害に弱い。不採用。
- OS の MSIX 署名のみ: アプリ本体には有効だが、フィルタには適用できない。併用する。
- Tauri のアップデータ: 署名検証の仕組みは参考になる [S35] が、製品では自前のクライアントを使う。

## 再検討のトリガー

- 署名鍵の漏洩。
- 更新の失敗率が高く、運用が回らない。
