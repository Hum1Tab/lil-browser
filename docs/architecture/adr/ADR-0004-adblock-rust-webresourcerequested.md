# ADR-0004: 広告遮断は adblock-rust + WebResourceRequested のハイブリッド

状態: 採用
日付: 2026-10-23

## 文脈

WebView2 にはブラウザ拡張が無い [S08]。したがって uBlock Origin は使えない。自前で遮断を実装する必要がある。adblock-rust は Brave の遮断エンジンで、ネットワーク遮断、cosmetic、スクリプトレット、uBO 構文を扱う [S22][S23]。

## 決定

- エンジン: adblock-rust（MPL-2.0）[S24]。
- ネットワーク遮断: `WebResourceRequested`。
- フィルタ登録: ドメイン事前登録 + 文書/スクリプト/XHR の全件フックのハイブリッド。
- cosmetic: 汎用 CSS + ナビゲーション後の `ExecuteScript`。
- スクリプトレット: 既定で無効。

## 理由

1. 全件フックは、すべてのリクエストをホスト UI スレッドとの往復にする [S10]。
2. ドメイン事前登録だけでは、パス・正規表現のルールを落とす。
3. ハイブリッドは、往復を重要なリソースに限定しつつ、遮断率を保つ。
4. `WebResourceRequested` は発信元フレーム URL を渡さない [S18]。したがって `$third-party` と `$domain` は近似になる。
5. スクリプトレットはページと同じ権限で動く。フィルタ更新経由の JS は、全ページの資格情報を窃取できる経路になる。

## 結果

- uBO と同等の遮断率は主張しない。
- `$csp` は非対応。`$removeparam` は `put_Uri` で部分対応 [S17]。
- YouTube の広告除去はベストエフォート。
- フィルタの更新は署名検証を必須にする。

## 代替案

- 全件フックのみ: 実装は単純だが、性能が悪い。
- ドメインのみ: 性能はよいが、パス系のルールを落とす。
- ローカルプロキシ: HTTPS の MITM が必要で、TLS の信頼を壊す。不採用。

## 再検討のトリガー

- WebView2 がフレーム URL を公開する。
- フィルタ登録の上限が低く、ハイブリッドが成立しない。
- 全件フックの実測コストが許容範囲に収まる。
