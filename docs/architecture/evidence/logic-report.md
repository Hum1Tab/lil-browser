# 論理監査レポート

日付: 2026-10-23
対象: `evidence/claims.csv` の 22 主張と、`12-final-recommendation.md` の結論
表記: `[TEXT]` = 資料に明記、`[CONV]` = 慣習的知識、`[ANALYST]` = 分析者の推論

## 1. 主結論の標準形

**結論**: 小規模チームが Windows 向けの軽量ブラウザを作る場合、エンジンは WebView2 を直接制御し、製品スコープを Google 認証と DRM の外に限定するのが最も妥当である。

**前提 1** [TEXT]: Chromium は 2 週間ごとにマイルストーンを出し、毎週セキュリティ更新を配信する [S29]。
**前提 2** [TEXT]: WebView2 は Edge と同じサンドボックスとサイト分離を使い、Evergreen で自動更新される [S05][S15]。
**前提 3** [TEXT]: WebView2 は拡張、Google OAuth、Widevine、Web Push、Payment を提供しない [S08][S20][S33]。
**前提 4** [CONV]: 1〜3 人のチームは、Chromium のセキュリティ更新に毎週追随する能力を持たない。
**前提 5** [ANALYST]: セキュリティ更新の遅延は、攻撃窓の拡大であり、セキュリティの後退である。
**前提 6** [ANALYST]: 実現できない互換性を約束しないことは、製品の信頼に資する。

**推論**: 前提 1〜5 から、fork はセキュリティを下げる。前提 3 から、WebView2 は完全代替にならない。前提 6 から、完全代替を約束せず、対象を限定する。したがって、WebView2 + 限定スコープが妥当である。

**妥当性**: 演繹的に妥当ではない。前提 4 と 5 は経験的で、反例があり得る（自動化された追随が可能な小規模チーム）。したがって「最善」ではなく「現時点で最も妥当」と表現する。

**隠れた前提**: 「性能の追求は、互換性の完全性より優先される」。これは価値判断であり、事実ではない。01 の 7 節で明示した。

## 2. 荷重主張の分析

### C01: WebView2 は拡張を提供しない

- 推論: 記述。公式の機能差表 [S08] が Off / Configurable=No と明記。
- 反例: 将来のバージョンで提供される可能性。
- 反証条件: 拡張 API の公開。
- 強さ: 強い。現行バージョンに関する限り。

### C02: Google は埋め込み WebView の OAuth を拒否する

- 推論: 記述。Google のブログ [S20]、Google の OAuth ドキュメント [S21]、Microsoft の機能差表 [S08] の三重の一致。
- 反例: ポリシーの変更。
- 反証条件: 再許可。
- 強さ: 強い。ただし「WebView2 が将来的に例外扱いされるか」は別問題。

### C04: WebResourceRequested は UI スレッド往復を伴う

- 推論: 機構。Microsoft のドキュメントが、ページ読込を止めてホスト UI スレッドを待つと説明 [S10]。
- 反例: フィルタを絞れば往復は減る。ただしゼロにはならない。
- 反証条件: 全件フックでも読み込み悪化が計測されない。
- 強さ: 中〜強。実測で「実務上問題ない」可能性は残る。

### C05: 発信元フレーム URL が無い

- 推論: 記述。イベント引数の型 [S18] と Request の型 [S17] に、フレーム URL が無い。
- 反例: Referer ヘッダから推定できる場合がある。
- 反証条件: API の拡張。
- 強さ: 強い。ただし「近似で十分」かは別問題。

### C06: Tauri は IPC ブリッジを全 WebView に注入する

- 推論: 記述。Tauri 本体のソース [S02] に、URL 条件なしの注入がある。
- 反例: capability でコマンド実行は拒否できる。
- 反証条件: 注入の停止。
- 強さ: 強い。「拒否できるから問題ない」とは言えないが、「直ちに脆弱性」とも言えない。

## 4. 相関と因果の混同チェック

- C09 は「サイト分離とメモリ増加」の関係を、公式の記述に基づいて記述している。因果の識別ではなく、ベンチマークの報告である。因果の主張としては使わない。
- C10 は「sleeping tabs とメモリ削減」の関係を、ベンダーの実験報告として記述している。交絡（タブの内容、時間）は統制されていない可能性がある。したがって「Edge の sleeping tabs が 32% 削減する」とは言わず、「Microsoft が 32% 削減と報告した」と言う。
- C18 は「fork が更新遅延を生み、セキュリティを下げる」という因果を含む。これは機構的推論であり、実証ではない。反例（自動化された追随）を認めた上で、小規模チームの現実的な能力を前提にしている。

## 5. 必要条件と十分条件

- 「更新を継続できる」は、セキュリティの**必要条件**であり、十分条件ではない。更新しても 0-day はある。
- 「WebView2 を使う」は、更新継続の**十分条件**ではない。Evergreen でも、実行中のプロセスは再起動まで旧版を使う [S15]。再起動の設計が必要である。
- 「Google ログインができる」は、日常利用の**十分条件**ではない。DRM、拡張、決済もある。
- 「ネイティブ UI にする」は、軽量性の**十分条件**ではない。エンジンのレンダラが支配的である。

## 6. 数量の扱い

- 32%、37%、10〜13% は、出典の文脈（時期、測定方法、対象）を伴って引用した。本製品の目標値に直接変換していない。
- 「2 週間」「毎週」は、リリースサイクルの記述であり、本製品の開発期間ではない。
- 250MB は、WebView2 の Fixed Version のサイズであり、CEF の実測値ではない。類推であると明記した。
