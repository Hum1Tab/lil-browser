# ドシエ（意思決定パッケージ）

日付: 2026-10-23
読者: 実装の可否を決める人、レビューする人

## 1. 結論

エンジンは WebView2 を直接制御し、UI はネイティブ、製品スコープは Google 認証と DRM の外に限定する。Tauri v2 は計測用の試作にだけ使う。

## 2. 最も強い反論

**「Google ログインが使えないブラウザは、ほとんどの人にとって日常使いにならない。」**

この反論は強い。Gmail、Google ドライブ、Google カレンダー、YouTube のログイン、多くの SaaS のソーシャルログインが Google に依存している。対象ユーザーが「Google ログインをブラウザ内で必要としない人」に限定されるなら、市場は小さい。

本稿はこの反論を否定しない。だからこそ、Phase 0 でユーザー調査を行い、Google ログインが必要な利用が 50% を超えるなら中止すると決めた。反論を消すのではなく、中止条件として受け入れた。

## 3. 反論への代替案と、それが解決しない理由

| 代替案 | 何を解決するか | 何を解決しないか |
|---|---|---|
| 外部ブラウザで OAuth | ネイティブアプリの API 連携 | 本ブラウザ内の Web サイトのログイン状態 |
| UA 偽装 | 一時的に通る可能性 | ポリシー違反、安定性、他のシグナル |
| Chromium フォーク | 互換性 | 更新追随、Widevine ライセンス、工数 |
| CEF | 制御性 | 拡張、DRM、認証の壁 |
| 既存ブラウザのラッパー | 軽量、安全 | ブラウザではない |

## 4. 既知の限界

1. 個別サイトの実機試験をしていない。
2. 性能を測っていない。
3. フィルタのライセンス解釈は法務確認前。
4. WebView2 の Cookie 暗号化の詳細は未検証。
5. InPrivate のディスク残留は未検証。
6. CEF と Chromium フォークの保守コストは推定。
7. Google 以外の OAuth（Microsoft、GitHub）の挙動は未検証。

## 5. 未解決の問い

| 問い | なぜ重要か | どう解くか |
|---|---|---|
| 対象ユーザーの Google 依存度 | 製品の成立可否 | 10 人程度の聞き取り |
| WebResourceRequested の実測コスト | 広告遮断の性能 | M0 の A/B |
| 5 タブメモリで Edge を下回るか | 軽量性の主張 | M0 の計測 |
| ネイティブ UI の工数 | 開発期間 | M1 の実績 |
| フィルタのライセンス | 配布の可否 | 法務確認 |
| パスキーの実機対応 | ログイン UX | M2 の実機試験 |

## 6. 価値前提

1. プライバシーは既定値で守る。
2. 使わない機能は無効化する。
3. 互換性の欠落は隠さない。
4. セキュリティ更新の速度を、自前実装の自由度より優先する。
5. 性能目標は実測で判定し、達成しなければ主張を撤回する。

これらは事実ではなく、選択である。異なる価値前提（例: 互換性を最優先、機能を最優先）なら、結論は変わる。

## 7. 結論が変わる条件

- Google ログインが必要なユーザーが 50% 超 → 中止または Chromium フォークの検討。
- 5 タブメモリと起動の両方で Edge を下回らない → 軽量性の主張を撤回。
- 全件フックの読み込み悪化が 10% 超 → 広告遮断の方式を変更。
- ネイティブ UI が M1 の 2 倍を超える → Web UI か WinUI 3 を再検討。
- フィルタのライセンスが解決できない → リストの変更。
- 外部監査で重大な脆弱性 → 設計の修正、リリース延期。

## 8. この文書の作成方法（AI 開示）

- 一次資料の取得と要約、設計文書の起草、論理監査の下書きに AI を使用した。
- 数値と引用は、取得した一次資料に基づく。ただし、個別サイトの挙動と性能は未検証である。
- AI は、存在しない出典を作らないように指示されたが、完全な保証はない。公開前に人間が URL と該当箇所を確認する。
- 最終的な採否は人間が決める。とくに、Google 認証の制約、フィルタのライセンス、セキュリティ監査の結論は、人間の確認を要する。

## 9. 読者への問い

1. 対象ユーザーは、Google ログインをブラウザ内で必要とするか。
2. 20〜50 タブのメモリで Edge に勝てない場合、製品の価値は残るか。
3. ネイティブ UI の工数を受け入れられるか。
4. フィルタのライセンスと、スクリプトレット無効の方針を受け入れられるか。
5. Phase 0 の結果で中止する覚悟があるか。

これらに答える前に、実装を始めない。
