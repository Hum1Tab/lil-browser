# 08. Web 互換性と制約

状態: 設計案（実機検証は未実施）
確信度: 中（プラットフォーム能力は一次資料で確認、個別サイトの挙動は推定）

## 1. 互換性クラス

本製品の互換性を、次の 3 クラスで定義する。

| クラス | 意味 | 本製品 |
|---|---|---|
| A: 完全代替 | Chrome/Edge と同じサイト・機能が動く | 該当しない |
| B: 対象限定 | 対象を絞れば日常利用できる | **該当する** |
| C: 実験用 | 限られたページだけ動く | 該当しない |

本製品は B である。「Chrome の代替」と表示しない。

## 3. Google 認証の壁

### 3.1 何が起きるか

Google は公式には、2021-09-30 以降、埋め込み WebView からの OAuth 認可要求を拒否する [S20]。エラーは `disallowed_useragent` になる [S21]。WebView2 は「埋め込み WebView」に該当するとされ、Microsoft の公式ドキュメントも Google 認証が無効であることを明記している [S08]。

**ただし、PX1 の実機試験（2026-10-23、Windows 11、WebView2 155）では、通常のログイン画面と OAuth の識別子画面が表示され、`disallowed_useragent` は出なかった [S47]。** ダミーメールを入力すると「アカウントが見つかりません」と表示された。完全ログイン、同意画面、Gmail、OAuth コールバックは未検証である。

公式文書と実機が矛盾する。どちらか一方を前提にせず、完全ログインの実機確認を Gate 0 にする。

### 3.2 なぜ「工夫」で解決できないとは限らないか

1. **UA 偽装は禁止する。** 要件にある通り、User-Agent の偽装や認証制限の回避を前提にしない。仮に UA を変えても、Google は他のシグナル（WebView の挙動、クライアントヒント、JS の特徴）で判定し得る。これは arms race であり、安定した設計にならない。
2. **外部ブラウザへの委譲は、アプリ内ログインを解決しない。** OAuth をシステムブラウザで行い、ループバックでトークンを受け取る方式は、ネイティブアプリの API 連携では有効である [S21]。しかし、Gmail や Google ドライブの **Web サイト**を本ブラウザで使う場合、Cookie は本ブラウザのプロファイルに無い。外部ブラウザでログインしても、本ブラウザのセッションにはならない。
3. **Google の拒否理由は、本設計の構造と一致する。** Google は「埋め込みホストが通信を傍受し、スクリプトを注入できること」を拒否理由に挙げている [S20]。本製品は広告遮断のために通信フックとスクリプト注入を行う。ただし、PX1 では即時ブロックされなかったため、この threat model が実際に適用される条件は未解明である。
4. **完全ログインを確認する。** 識別子画面が表示されても、同意画面や Gmail が通るとは限らない。使い捨てアカウントで、OAuth の同意、Gmail、再ログインを確認する。資格情報は保存しない。

### 3.3 代替

- 完全ログインが通らない場合に限り、Google アカウントが必要なサイトを既定のブラウザで開くボタンを提供する。
- 本ブラウザ内でのログインは、PX1 で通った範囲だけ提供する。
- 「Google ログインが必要なサイト」を事前に検出し、案内を出す（サイトリストはローカル）。

## 4. DRM の壁

### 4.1 事実

- 公式には、WebView2 は PlayReady を扱うが Widevine は未提供とされてきた。Widevine 対応の機能要望がオープンになっている [S33]（部分的証拠）。
- **PX4 の実機試験（2026-10-23、Windows 11、WebView2 155）では、`com.widevine.alpha` と `com.microsoft.playready` の両方が `requestMediaKeySystemAccess` で supported を返した [S48]。** `org.w3.clearkey` も supported だった。
- Netflix のトップと Spotify Web は表示された。ログイン前のため、再生は未検証である。
- Bitmovin の DRM デモは、manifest の読み込みに失敗した（`SOURCE_COULD_NOT_LOAD_MANIFEST`）。DRM ライセンスの失敗か、ネットワーク・同意ダイアログ・CORS の失敗かは未切り分けである。
- Netflix、Amazon Prime Video、Disney+、Spotify などは Widevine を要求する。
- CEF にしても、Widevine の同梱にはライセンスが必要で、無条件には解決しない。

### 4.2 影響

- EME が supported でも、実際の再生、ライセンス取得、HDCP、robustness、Netflix のポリシーは別である。
- 実再生が通れば、動画配信の視聴ができる可能性がある。通らなければ、対象外にする。
- 一部の企業研修（eLearning）が Widevine を使う場合、実再生の確認が必要である。
- H.264 の通常動画（YouTube の一般動画、SNS の動画）は再生できる見込み。

### 4.3 代替

- 実再生が通らない場合に限り、DRM が必要なサイトを既定のブラウザで開く。
- 実再生が確認できるまで、本ブラウザを「動画視聴用」と位置づけない。
- 実再生の確認は、公開の Widevine テストストリームと、使い捨ての Netflix アカウントで行う。資格情報は保存しない。

## 5. 拡張機能の壁

- WebView2 はブラウザ拡張を提供しない。設定もできない [S08]。
- したがって uBlock Origin、Bitwarden、Dark Reader などの Chrome 拡張は使えない。
- 広告遮断は自前で実装する（06）。
- パスワード管理は保存しない方針のため、拡張の代替も提供しない。ユーザーは OS のパスキー/資格情報マネージャーを使う。

## 6. その他の欠落

| 機能 | 影響 | 代替 |
|---|---|---|
| Web Push | タブを閉じると通知が来ない | タブを開いたままにする。メールは別クライアント |
| Web Payment | Web 決済が動かないサイトがある | 既定のブラウザで開く |
| Periodic Background Sync | オフライン同期が動かない | オンライン時に同期 |
| PDF 注釈 | 署名・注釈ができない | 外部 PDF ビューア |
| ブラウザ Task Manager | タブごとのリソース表示ができない | 自前の簡易表示 |
| `edge://` 設定 | 一部の設定にアクセスできない | 自前の設定 UI |
| 自動翻訳 | 翻訳 UI が無い | 翻訳サイトを開く |
| 読み上げ | 無い | OS のナレーター |

## 7. パスキー / WebAuthn

- WebView2 でパスキーのプロンプトが表示される事例がある [S34]。
- 一方で、Windows Hello のプラットフォーム認証器が WebView2 で使えないという報告がある [S38]。`isUserVerifyingPlatformAuthenticatorAvailable()` が false になり、プロンプトが出ないという内容である。
- **PX1 の実機試験（2026-10-23、Windows 11、WebView2 155）では、`UVPAA=true` を返し、webauthn.io と GitHub の passkey 操作で `Windows Security` のプロンプト（CredentialUIBroker）が起動した [S47]。** 報告と実機が矛盾するため、環境依存と判断する。
- 認証の完了、登録した資格情報の再利用、attestation は未検証である。
- パスキーの保存・同期は OS とエッジの管理下にあり、本製品の UI では制御できない。
- 企業のセキュリティキー運用（FIDO2）は未検証。SAML と組み合わせる場合、証明書選択やプロキシの挙動も確認が必要。

【設計判断】パスキーを「対応」と表示しない。主要サイトで登録と認証が完了するまで「条件付き（未検証）」とする。認証完了が通らない場合は、パスキー必須のサイトを対象外とし、必須要件にするなら WebView2 は失格である（13 の F1）。

## 8. ボット判定・互換性の暗礁

- Cloudflare などのボット判定は、UA、JS の特徴、Cookie の有無、ヘッドレス判定など複数のシグナルを使う。WebView2 は「組み込みブラウザ」として扱われる可能性がある。
- 銀行、行政、決済サイトは、未対応ブラウザを明示的に拒否することがある。
- これらは事前に全リスト化できない。ユーザーからの報告と、サイト別の「既定のブラウザで開く」導線で緩和する。

## 10. 制約の表示

製品内の「このブラウザでできないこと」画面に、次を明記する。

- Google の完全ログイン（PX1 では識別子画面まで。同意画面と Gmail は未検証）
- Netflix などの DRM 動画
- Chrome 拡張機能
- Web Push 通知
- Web 決済の一部
- PDF の注釈・署名
- 一部サイトのボット判定

これを隠さないことが、製品の信頼の一部である。
