# PX3: メモリ・起動プローブ結果（初期）

日付: 2026-10-23
環境: Windows 11 Home 10.0.26200、WebView2 Runtime 155.0.4283.62、.NET SDK 8.0.426
コード: [`prototype/px3-tabs/`](../px3-tabs/)、計測: [`prototype/px3-measure.ps1`](../px3-measure.ps1)
ページ: [`prototype/px3-server/server.py`](../px3-server/server.py)（10 枚の画像、ローカル）
生データ: [`prototype/results/px3-ours-*`](../results/)、[`px3-edge-*`](../results/)

## 1. 目的

「1 / 5 / 20 タブの総メモリと起動で Edge を上回れるか」を、初期の実測で確認する。これは Gate 1 の中心である。

## 2. 方法

- **本プロトタイプ**: WinForms + WebView2。1 ウィンドウに `TabControl` を置き、タブごとに `WebView2` コントローラを作る。`CoreWebView2Environment` は 1 つを共有。各タブは同じローカルページを開く。全タブの読み込み完了後に `ready.json` を書き、25 秒保持する。
- **Edge**: 新しい `--user-data-dir`、`--no-first-run`、`--disable-sync`、`--disable-background-networking` で起動。N 個の URL を `--new-window` で渡す。10 秒待ってから計測。
- **メモリ**: プロセスツリー全体の `PrivateMemorySize64` と `WorkingSet64` を合計。本プロトタイプはホスト PID と、UDF をコマンドラインに含む `msedgewebview2.exe` の子孫。Edge はプロファイルをコマンドラインに含む `msedge.exe` の子孫。
- **起動**: 本プロトタイプは `Process.StartTime` から `ready.json` まで（全タブの読み込み完了）。Edge は `Start-Process` からメインウィンドウハンドルが現れるまで。

各条件 1 回。ページは軽量（10 画像）、同一オリジン。

## 3. 結果

### 3.1 メモリ

| タブ | 本 Private | Edge Private | 差 | 本 Working Set | Edge Working Set | 本プロセス数 | Edge プロセス数 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 204.3MB | 372.7MB | **-45.2%** | 475.5MB | 760.6MB | 9 | 15 |
| 5 | 289.9MB | 493.9MB | **-41.3%** | 651.9MB | 1013.9MB | 12 | 20 |
| 20 | 768.5MB | 851.7MB | **-9.8%** | 1601.3MB | 1811.2MB | 27 | 34 |

### 3.2 起動

| 条件 | 本（全タブ読込完了） | Edge（ウィンドウ表示） |
|---|---:|---:|
| 1 タブ | 1,435ms | 369ms |
| 5 タブ | 7,016ms | 806ms |
| 20 タブ | 9,860ms | 798ms |

**この比較は公平ではない。** 本プロトタイプは全タブを順に生成・読み込みしてから `ready.json` を書く。Edge の `windowMs` はウィンドウが出た時点で、ページの読み込み完了ではない。20 タブの 9.9 秒は、設計が想定する「URL だけ復元し、必要になったら生成する」遅延復元を実装していない。

### 3.3 タブ切替

- `TabControl.SelectedIndex` を変えて 30ms 待ち、`ExecuteScriptAsync("document.title")` の往復を測った。
- 1 タブ: 2ms。5/20 タブ: 0〜2ms。
- これは描画の present ではなく、スクリプト往復の proxy である。タブ切替の体感時間の判定には使えない。

## 4. 解釈

1. **1 タブと 5 タブでは、本プロトタイプの Private メモリが Edge を大きく下回った。** 1 タブ -45%、5 タブ -41%。ホストの固定費が小さいこと、Edge の UI・バックグラウンドプロセスが無いことが効いている。
2. **20 タブでは差が -9.8% に縮む。** タブ数が増えると、レンダラと GPU のコストが支配的になり、ホストの差が相対的に小さくなる。設計の予測（20 タブで Edge の ±10%）と整合する。
3. **起動は未判定。** 本プロトタイプの 1 タブ 1.4 秒は、Edge のウィンドウ表示 0.37 秒より遅い。ただし、本側はページ読み込み完了を含み、Edge 側は含まない。公平な比較には、両方の「最初のタブのページ読み込み完了」を測る必要がある。
4. **20 タブの起動 9.9 秒は、設計の遅延復元を実装していないための値である。** 製品設計では、起動時にアクティブタブだけを生成し、他は URL だけ復元する。この値を持って「起動が遅い」と結論しない。
5. **同一オリジンの軽量ページである。** 20 の異なるサイト、動画、SPA では、レンダラの分割とメモリが増える。差が維持されるかは未検証。

## 5. 設計への影響

- Gate 1 の「5 タブメモリ」は、初期実測では **合格方向**。ただし 1 回、軽量ページ、同一オリジンである。
- 「起動が Edge より速い」は **未証明**。PX3b で公平に測る。
- 「20 タブで Edge より軽い」は、初期実測では **-9.8%** で、辛うじて下回る。誤差と実サイト次第なので、主張には使わない。
- F3（差別化の未証明）は、「メモリは支持、起動は未証明」に更新する。

## 6. 限界

- 各条件 1 回。分散を測っていない。
- ローカル、軽量、同一オリジン。実サイトのレンダラ分割、動画、Service Worker、広告を含まない。
- Edge の sleeping tabs は 10 秒では発動しない。両方とも「アクティブ 20 タブ」の比較である。
- Edge のバックグラウンドサービスを完全には止めていない。
- 本プロトタイプはタブのサスペンド・破棄を実装していない。
- プロセスツリーの帰属はコマンドラインと親子関係に依存する。取りこぼしの可能性がある。
- 起動の定義が異なる（全タブ読込 vs ウィンドウ表示）。

## 7. 次の試験（PX3b）

1. 最初のタブだけを読み込み、他は URL だけ復元する「遅延復元」を実装する。
2. 本と Edge の両方で、最初のタブの `loadEventEnd` を CDP で測る。
3. 5 回以上、中央値と p95。
4. 実サイト 20 件（異なるオリジン）で 1/5/20 タブを測る。
5. タブのサスペンド（`TrySuspendAsync`）と破棄を実装し、メモリと復帰時間を測る。
6. タブ切替は `PresentMon` で present まで測る。
