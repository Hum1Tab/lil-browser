# コード分析の枠組み

目的: 20 人のインタビューを、H1〜H5 の判定に使える形で整理する。印象ではなく、発言と行動の件数で示す。

## 1. 演繹コード（H1〜H5）

| コード | 定義 | 主な H | 例 |
|---|---|---|---|
| `MEM` | メモリ、重さ、タブ数、PC への負荷 | H1 | 「10 タブ開くと PC が重い」 |
| `PRIV` | 追跡、テレメトリ、プライバシー、InPrivate | H1 | 「Telemetry を切っても残るのが嫌」 |
| `SPEED` | 起動、ページ表示、待ち時間 | H2 | 「起動が遅いのは許容できる」 |
| `COMPAT` | 拡張、Google ログイン、Netflix、サイト互換性 | H2 | 「uBlock が使えないなら無理」 |
| `UI` | タブ、アドレスバー、履歴、設定の使いやすさ | H4 | 「タブの並べ替えができないと困る」 |
| `WORKAROUND` | タブを閉じる、再起動、別ブラウザ、拡張で対処 | H1 | 「定期的にブラウザを再起動する」 |
| `DEALBREAKER` | 採用を止める制約 | H2 | 「Netflix が見られないなら使わない」 |
| `TRUST` | 安全性、更新、供給元、権限 | H2/H5 | 「小さいチームの更新は不安」 |
| `PRICE` | 無料/有料、支払い意思 | H5 | 「月 500 円なら払う」 |
| `SKEPTIC` | 懐疑、乗り換えない理由 | H1/H2 | 「Edge で十分」 |

## 2. 帰納コード（必要なら追加）

演繹コードで拾えないテーマが出たら、最大 5 個まで追加する。追加したら定義と例を書き、全員のメモに遡って適用する。

例:

- `SYNC`: 端末間の同期。
- `BATTERY`: ノート PC のバッテリー。
- `WORK`: 仕事のタブと私用の分離。
- `SECURITY`: フィッシング、パスワード、資格情報。

## 3. コーディング手順

1. 文字起こしを読み、発言ごとに 1 つ以上のコードを付ける。
2. 「事実」（行動、出来事）と「意見」（好み、評価）を分ける。
3. 制約のカードソートは、`DEALBREAKER` と `COMPAT` に対応させる。
4. 価格の発言は `PRICE`。
5. 否定的な発言も必ずコード化する。都合の良い発言だけ残さない。
6. コードが付かない発言は、無理に付けない。`OTHER` として残す。

## 4. 件数の数え方

- **人ベース**: 1 人が複数回言っても 1 件。H1/H2 の判定は人ベース。
- **発言ベース**: 引用の強さを見る補助。人ベースと混ぜない。
- `DEALBREAKER` は、カードソートで「致命的」に置いた制約の数を人ごとに数える。
- 「たぶん」「かもしれない」は、肯定として数えない。

## 5. 信頼性チェック

- 2 人が独立して 5 本の文字起こしをコード化する。
- コードの一致率を測る（単純一致で 70% 以上を目安）。
- 不一致は、定義の曖昧さを直す。 participant の発言を勝手に解釈しない。
- 一致率が低いコードは、分析から外すか、定義を書き直す。

## 6. 分析の出力

### 6.1 テーマ表

| テーマ | 人ベース件数 | 代表引用 | H |
|---|---:|---|---|
| タブを開くと重い |  |  | H1 |
| 拡張が手放せない |  |  | H2 |
| 起動の遅さは許容 |  |  | H2 |
| 価格に敏感 |  |  | H5 |

### 6.2 セグメント比較

- 10 タブ以上 / プライバシー / Edge・Chrome 常用で、`MEM`、`PRIV`、`COMPAT` の件数を比較する。
- セグメントごとに 5 人前後なので、傾向のみ。統計的検定はしない。

### 6.3 制約のマトリクス

| 制約 | 致命的 | 許容 | 気にしない | 合計 |
|---|---:|---:|---:|---:|
| Chrome 拡張なし |  |  |  |  |
| Google 完全ログインなし |  |  |  |  |
| Netflix なし |  |  |  |  |
| 起動が遅い |  |  |  |  |

### 6.4 引用バンク

- 肯定・否定・条件付きを同数程度集める。
- 個人特定情報を除く。
- 引用を 1 人だけに偏らせない。

## 7. 判定への接続

- H1: `MEM` または `PRIV` を上位 2 つに置いた人数 / 有効回答者。
- H2: `DEALBREAKER` が 2 つ以下の人数 / 有効回答者。
- H3: ランディングページの登録率（`metrics.json`）。
- H4: プロトタイプ実施者の 1 週間継続 / 実施者。
- H5: `PRICE` で ¥500/月 または ¥3,000 買い切りを許容した人数 / 有効回答者。

## 8. やってはいけないこと

- 1 人の強い引用で、全体の傾向を語る。
- 否定意見を「例外」として捨てる。
- コードの件数と、発言の強さを混同する。
- 統計的な代表性を主張する（n=20〜50）。
- 参加者の言葉を、製品のコピーに都合よく言い換える。
